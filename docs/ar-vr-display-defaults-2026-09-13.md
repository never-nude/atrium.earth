## Selection provenance

Choices use the effective catalog title (including identity-title corrections), readable slug terms, and named object types checked in the catalog notes. They do **not** use catalog dimension strings, physical-dimension records, uncertain measurements, source-native units, model bounds as evidence of real size, or museum dimensions to infer physical truth. Codex chose the numerical presets for display; they are not sourced facts.

Rule precedence is: individual object-type choices; detail/ornament terms (including netsuke and miniature); handheld/container terms; explicitly standing/seated portraits; head/bust/mask/torso terms; medium general objects (including shields, tusks, instruments, tablets and fragments); figure/architecture terms; named figure/deity subjects; neutral 1 m fallback. This keeps a head-shaped vessel in the vessel class, a Noh-mask netsuke in the detail class, and miniature architecture from becoming a 1.5 m architectural display.

Selection totals: 175 general fallback; 40 individual object-type choice; 583 ordered title/slug rule. Each row carries its selected rule term or individual object-type reason and explicitly says it is not a physical measurement. An ambiguous title keeps the neutral 1 m fallback rather than asserting an object size.

## Runtime contract

Display these entries as **chosen starting sizes** and permit resizing. Preserve verified-reference labels and fixed physical scale only for works that pass the existing verification path. A chosen default must not create a documented/original-size badge, rewrite physical measurements, or bypass an integrity check for a model that claims verified scale. No physical-dimension, eligibility, model, or hash files were changed for this selection.

## Access and validation

`Work.spatialAccess` controls whether a compatible GLB offers AR/VR. The existing `spatialEligibility` contract independently controls verified-size presentation. All 1,046 public works have access: 248 reviewed references and 798 explicit default displays. An invalid or unfinished measurement never supplies the default size. Verified paths retain model-byte SHA-256 checks and fixed sizing.

Unverified cards and work controls show red **Size unverified** text and the chosen maximum dimension. Launch dialogs repeat that the dimension is a display choice. The index's size-status filter separates reviewed and unverified displays. WebXR defaults allow resizing and reset to the chosen size. Apple defaults allow pinch resizing unless the visitor includes a virtual stand; that assembly keeps its prepared size to preserve the stand's dimensions. Native Apple AR cannot carry the webpage's warning overlay, so the warning appears before launch.

Validation: all 1,046 access decisions and all 798 presets checked; existing dimension, verification, rendering, display-support and spatial tests passed. Chrome and WebKit each prepared Laocoön and Dubuffet at 1.5 m maximum extent, with resizing enabled; the reviewed Ushebti retained 0.09 m height and fixed sizing. Serialized USDZ bounds matched targets within 0.1 mm, including existing quantization, a numerical export check rather than evidence of real-world size. Fourteen discovery checks covered filtering, URL retention and layouts from 320 to 1,440 px, with no JavaScript errors. No new native-phone outdoor or physical-headset validation is claimed.
